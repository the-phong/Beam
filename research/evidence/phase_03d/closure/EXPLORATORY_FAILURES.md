# Exploratory failures retained

The complete raw output of two later failed commands is preserved verbatim in `exploratory_make_verify.log` and `exploratory_m11_build_failure.log`. Earlier interactive `go test` attempts were shown in the tool transcript but were not redirected to a file at execution time; the following are contemporaneous diagnostic excerpts, **not claimed as full raw logs**. The final fault tests were rerun with full output redirected to `m4_store_faults.log`, `m11_store_faults.log`, `real_node_faults.log`, `m4_process_kills.log`, `mismatch_extra.log` and `raw/`.

1. Initial direct in-process WAL-write error: `go test ./internal/b0store -run 'TestM4ReturnedWALWriteAndSyncErrors|TestM11GenesisCreationFaultBoundaries' -count=1 -v` exited 1 while running the first M4 subtest. Pebble printed `pebble: fatal commit error: injected error` and terminated the test process. The harness was changed to inject in a disposable subprocess, so parent tests can inspect durable state after the fatal exit.
2. First WAL-sync injector attempt used Pebble `errorfs.OpFileSync` and exited 1 because neither the M4 nor M11 target marker was reached. The child completed `Commit` successfully. Inspection of pinned Pebble v1.1.5 `vfs/errorfs/errorfs.go` showed that `SyncData` and `SyncTo` forward directly without injected errors. The harness now wraps those file methods and records the actual reached method in a marker file.
3. After adding the sync wrapper, an M11 exploratory run exited 1 at `wal-sync unexpectedly opened`. The target sync fault **was reached**; reopening found a complete, integrity-valid H0 record. The assertion was corrected to accept either an intact complete record or explicit fail-closed incomplete state after an uncertain sync outcome. The final test logs the observed complete H0 state and matching genesis hash.
4. The first `make verify` after a before-mkdir probe exited 2. `OpenExisting` returned an error for an absent directory but Pebble created the path as a side effect, causing the test's fresh retry to receive `ErrExisting`. The exact output is in `exploratory_make_verify.log`. `OpenExistingWithOptions` now checks the path before Pebble, and final `make verify` exited 0.
5. The first M11 subprocess-kill test build exited 1 for `undefined: bytes` in the test file. The exact compiler output is in `exploratory_m11_build_failure.log`; the import was added, and the final test exited 0.

No exploratory failure was reclassified as a PASS. The final software-fault PASS statements require the marker and durable-state assertions in the staged test sources; physical power loss remains untested.
